# 1件のマージ（`merge`）

## 目的

名指しされたプルリクエストを1件だけ、既存の入口と検査を順に通してマージする。
このスキルは手順の順番を固定するだけで、マージしてよいかを自分では判断しない。
判断はすべて手元の作業場にある検査入口に任せ、拒否されたらそこで止まる。

## 前提条件

この手順が呼ぶスクリプトの一部は、**このリポジトリには無い**。
`shared/scripts/` を持つ手元の作業場から実行することを前提とする。

- `shared/scripts/pr_merge_guarded.py`: マージの唯一の入口。既定では試し実行だけをする
- `shared/scripts/local_ci_equivalent.py`: `GitHub Actions` が起動しない時に、同じ検査を手元で行う

スクリプトが見つからない時は、**代わりを自作せず、そこで止めて報告する**。
`gh pr merge` を直接実行して入口を迂回しない。

引数の名前と取りうる値は、この文書に写さない。
毎回 `pr_merge_guarded.py --help` を正本として読む。
写した表は過去に実物とずれて事故を起こしている。

## 必要な入力

- 対象のリポジトリ（`owner/name` の形）と、プルリクエストの番号。どちらかが不明なら推測せず、1問だけ確認する
- 今の会話での、そのプルリクエストへのマージの承認。承認の言葉はそのまま控えておく

## 手順

1. **名義を確かめる。** `github-cli-ops-guard` の手順で、`gh` の有効なアカウントが対象のリポジトリに合っているかを確かめる。ずれていたら、切り替えずに止まる。
2. **すべてのやり取りを読む。** `pr-status` の手順で、検査の結果・競合・レビューを確かめる。未解決のレビュースレッドは、このリポジトリの `scripts/github_pr_review_thread_audit.py --repo <owner/name> --pr <番号> --json` で数える。未解決のスレッドや新しい指摘があれば、マージに進まず報告する。
3. **検査の状態で経路を決める。**
   - 検査が通っている時は、通常の経路で手順4へ進む。
   - 検査が実行されて失敗している時は、止まる。実際のテストの失敗は、どの経路でも代わりにならない。
   - 課金や利用上限で検査が起動していない時は、手元の作業場の運用規則（`AGENTS.md` の該当する節）の条件をすべて満たす時だけ、`--ci-unavailable` の経路を使う。条件は、非公開のリポジトリであること、全ジョブが起動しなかった根拠、`local_ci_equivalent.py` による対象 `head` の完全な検査記録、独立したレビューの記録の4つ。1つでも欠けたら止まる。
   - `--break-glass` は使わない。
4. **許可の値は、実際の承認のされ方から選ぶ。** 決め打ちにしない。
   - 承認の参照（`--approval-ref`）には、ユーザーの承認の言葉をそのまま入れる
   - 人間のレビューを省略したという申告（`review_waived_current_turn`）を既定にしない。自分が作ったプルリクエストでこれを使うと、自己承認として止められる
5. **先に試し実行をする。** `--execute` を付けずに `--json` で実行し、許可の判定が `allow` かを確かめる。この時点の `head` の値を控えておく。
6. **`allow` の時だけ、同じ引数に `--execute` を足して実行する。** 引数を変えて再試行しない。
7. **マージを実測する。** `GitHub` の画面の表示だけで済ませない。プルリクエストの状態が `MERGED` で、マージされた `head` が手順5で控えた値と一致するかを読み直す。
8. **後片付けと最終確認は `post-merge-closeout` に渡す。** 作業ツリーやブランチの削除は、そのスキルの承認条件に従う。

## 止まる時

検査入口・`hook`・自動実行の分類器のどれかに拒否されたら、**1回で止まる**。
語彙や手段を変えて同じ操作を繰り返さない。別のエージェントに回して迂回しない。

報告は次の形の1行にする。

```text
マージ未実行: <何が止めたか>。次の1手: <ユーザーがやること1つ>
```

例:

```text
マージ未実行: 未解決のレビュースレッドが2件。次の1手: スレッドに返答して解決にする
マージ未実行: 自己承認として分類器が拒否。次の1手: ブラウザでプルリクエストを確認してマージする
```

## 完了の報告

- 「レビュー済み」と「マージ済み」を混ぜない。手順7の実測が通るまで、完了と言わない
- プルリクエストは「リポジトリ名と番号」で書く。番号だけにしない
- 手元の検査で代用した時は、`GitHub Actions` が起動しなかった理由・検査した範囲・検査していない範囲を書く。手元の検査の成功を `GitHub Actions` の成功と言い換えない
