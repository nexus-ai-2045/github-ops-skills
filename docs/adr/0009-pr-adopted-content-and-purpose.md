# ADR-0009: プルリクエスト作成前に採用済み内容と枝の目的を検査する

## 状態

提案。ローカル実装・検証まで。公開と採用は人間レビュー後。

## 背景

既存のプルリクエスト作成入口は名義・権限・対象コミットを照合するが、採用済み変更を古い基準に適応した枝から再提案することを防げない。過去の発行ツールがこの入口だったかは未確定であり、全経路の再発防止とは扱わない。

## 判断

既存の `pr_create` の送信前検査に `Git` の三者統合検査を追加する。固定した基準・先端を使用し、統合結果が基準と同じなら採用済み・差分なしとして拒否する。競合・履歴不足・同じファイルへの並行変更・採用済みと固有変更の混在は自動作成せずレビューへ返す。固有の文書変更は通す。

`--branch-purpose resident_adaptation` は常駐への適応用であり作成を拒否する。省略時の `development` は既存呼出しとの互換性を保つ。枝名から目的を推測せず、申告だけを重複判定の根拠にもせず、内容検査を併用する。

## 保証と限界

保証は `Git` の履歴・`tree`・`mode/blob` の一致と、実際にこの入口を利用した作成に限定する。別実装の意味的同値、誤った目的申告、直接 `gh pr create` を使う別経路まで保証しない。`git cherry` のみで採用を判定しない。改行や復号不能文字など、現コマンド実行器で正確なパス取得を保証できない対象は不明として停止する。新しい台帳・常駐処理・設定変更は追加しない。

## 検証

実際の `Git` 履歴で固有文書、全採用、古い基準への適応、部分採用、同一ファイルの部分採用、競合を検査する。送信前停止と既存の送信後結果不明・再送禁止の契約を回帰試験する。
